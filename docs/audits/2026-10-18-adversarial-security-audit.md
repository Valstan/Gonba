# Состязательный security-аудит одним заходом — 18.10.2026

**Роль:** закрытие пункта `#057` («состязательный security-аудит одним Workflow», D-096, очередь 2, срок 30.11).
**Форма:** fan-out по шести измерениям → дедуп → **опровержение по умолчанию** (каждый кандидат проходил скептика-опровергателя) → синтез по тяжести. Отчёт **обязан печатать покрытие** — [pool #293](../../../brain_matrica/cross-project-ideas/ideas/293-a-fan-out-review-must-report-its-coverage.md): мёртвое измерение даёт тот же нуль, что и чистое.

**Статус:** правки приложения — в этом же PR; часть находок требует владельца (`#025`) или отдельного окна; ниже это помечено явно.

## 1. Как проводился (и чем не является)

- **Режим — статический.** Прод не зондировали, эксплуатацию не выполняли, прод-данные не меняли. Единственные живые обращения: `GET /api/health` (200), чтение файлов и свойств юнитов на боксе — обе операции read-only.
- **Шесть измерений** (по искателю на каждое): `unauth-external`, `authed-insider`, `rogue-client`, `data-at-rest-and-transit`, `supply-chain-ci`, `infra`. Каждый искатель работал по **одной** преамбуле (единый формат находки: файл+строки, путь эксплуатации, предпосылки, влияние, уверенность, `what_i_did_not_check`).
- **Опровержение по умолчанию.** Кандидат считался находкой только после вопроса «а что мешает это сделать?»; часть кандидатов снята контр-доказательствами (в том числе из вендорного кода в `node_modules`).
- **Адверсариальный контроль поверх fan-out:** три отдельные проверки (дерево деплоя; uid/секреты; uid/root) с презумпцией ложности находки. Две из трёх вернулись с **поправками к механизму**, но подтверждением класса — severity пересчитана, а не унаследована.
- **Чем отчёт не является:** это не пентест и не доказательство. Живых эксплуатаций не было ни одной; для ряда находок остаётся «нужна живая проба» (они помечены).

### 1.1 Честная оговорка о сохранности артефактов

Сырые отчёты искателей и рабочие заметки жили в `/tmp/opencode/audit-057/` и к моменту написания отчёта **недоступны** — каталог снесён сменой сессии улья (не метёлкой `/tmp`: `opencode-tmp-sweep` удаляет только файлы вида `*-00000000.so`/`.dylib`, что проверено по её скрипту). Поэтому:

- находки ниже — те, что **проверены лично оркестратором** или пришли от скептиков с полным текстом;
- для измерений `supply-chain-ci` и `data-at-rest-and-transit` сохранён полный счёт кандидатов, но **не все формулировки**; это отмечено в таблице покрытия;
- сама эта утрата — урок (см. §7): артефакты многоагентного прогона пишутся туда, где их не снесёт смена сессии.

## 3. Подтверждённые находки

Тяжесть — по шкале преамбулы (critical = путь без аутентификации до полного контроля; high = путь без аутентификации либо с любой учёткой с серьёзным влиянием; medium = нужны повышенные права или влияние ограничено; low = гигиена).

### HIGH

**H-1. Удаление «своей» публикации удаляло чужой файл** (rogue-client; `web/src/app/api/ugc/delete-submission/route.ts`, `web/src/server/ugc/s3.ts`).
Ключи объектов приходят от клиента — сервер проверял только **формат** (`media/lenta/...`). Уникальность верхнего `objectKey` обходится через `media[]`, где такого ограничения нет. Путь: взять публичный чужой ключ из ленты → создать свою публикацию со ссылкой на него → `POST /api/ugc/delete-submission` → `DeleteObjectCommand` без проверки префикса и владельца. Проверка владения отвечает на «твоя ли запись», а не «твой ли файл». Влияние: аноним вычищает медиа любого чужого поста (битые картинки, «битая» лента), при повторе — весь бакет.
**Вылечено в этом PR:** `selectDeletableKeys` — удаляются только ключи, на которые не ссылается другая публикация (включая `media[]`), ошибка поиска трактуется как «ссылка есть»; +5 юнит-тестов.

**H-2. «Аутентифицирован» читалось как «персонал» — анти-абуз UGC выключался любой учёткой** (authed-insider; пять хуков `web/src/server/ugc/hooks/rateLimit*.ts`, ключевое место — `rateLimitSubmission.ts`).
`if (req.user) return data` в пяти хуках: любая учётка коллекции `users` (роль `user`/`support`/`manager`) отключала лимиты, дедуп и проверку ключей. Последствия: три жалобы подряд **авто-скрывали** чужую публикацию (порог `UGC_REPORT_HIDE_THRESHOLD`), счётчики лайков/просмотров накручивались, а в паре с `media[].objectKey` без field-access та же учётка удаляла чужие файлы (см. H-1).
**Вылечено:** общий `isContentStaff` (admin|editor) + инвариант-тест, запрещающий возврат `if (req.user) return`.

**H-3. Плагинные коллекции: ПДн заявок читал и удалял любой аккаунт; адресаты уведомлений правились любым** (authed-insider; `web/src/plugins/index.ts`, дефолты `plugin-form-builder`).
`form-submissions`: дефолт плагина — `read: req.user?.collection === config.admin.user` (истинно для **любой** роли), `delete` не задан → дефолт ядра `Boolean(user)`. `forms`: права на запись не заданы вовсе → `PATCH /api/forms/:id` с подменённым `emailTo` уводит **все последующие** заявки сайта на чужой адрес. `redirects`: задан только `read` → любая учётка создаёт редирект с нашего домена на чужой (открытый редирект/фишинг) и правит/удаляет настоящие. `search`: правка/удаление индекса — любому.
**Вылечено:** явные `create/update/delete: adminOrEditor` (для `form-submissions` — `read`/`delete`) + инвариант-тест по каждому блоку.

**H-4. IP клиента брался из первого хопа `X-Forwarded-For`** (unauth-external + адверсариальный контроль; `web/src/utilities/getRequestIpHash.ts`, `web/src/server/ugc/ugc.ts`).
Первый хоп задаёт сам клиент. Подставляя его, аноним получал свежую корзину на каждый запрос: лимиты UGC/чата/заявок, дедуп реакций и жалоб, порог авто-скрытия — всё обнулялось, а `ipHash` (хранимый «псевдоним» IP) переставал что-либо значить. Класс у Мозга — G413.
**Вылечено:** единый `extractClientIp` (`X-Real-IP` → **последний** хоп `X-Forwarded-For` → `null`), используется и в хеше, и в лимитах; +11 тестов, включая «шесть разных подставленных IP = один бакет».

**H-5. Улей (агент на боксе) и прод делят uid — агент читает прод-секреты** (infra + скептик; owner-gated).
Замеры: `/etc/gonba/gonba.env` — `640 root:valstan`, читается; тот же inode виден и в пространстве имён прод-сервиса; `/proc/<gonba>/environ` читается целиком (38 переменных, значения непусты — **имена** только: `DATABASE_URL`, `PAYLOAD_SECRET`, `CRON_SECRET`, `S3_*`, `YANDEX_DISK_TOKEN`, `VK_*`, `DEEPSEEK_API_KEY`). Политика улья закрывает **действие** `read:/etc/gonba/*`, но не файловое чтение через `shell` — правил на это нет, обход тривиален. Опровергнуто: вариант через `/proc/*/mem` (yama=1) и через корку (core limit 0) — не работает, и он не нужен.
**Требует владельца:** разные uid улья и прода, `InaccessiblePaths=/etc/gonba` (+`ProtectSystem=strict` и явный `ReadWritePaths`), `chmod 600 root:root` на env-файл и его бэкапы, root-owned `authorized_keys`. Запись в `docs/followups/`.

**H-6. Путь улей → root одной командой** (infra + скептик; owner-gated).
`user@1000.service` живёт **без** `NoNewPrivileges`, `systemctl --user` доступен → транзиентный юнит стартует вне cgroup улья и `sudo -n` работает (NOPASSWD документирован в `docs/PROJECT.md` и ADR как «полный root-доступ»). Дополнительно: деплой делает `sudo cp` с произвольными src/dst и `sudo <скрипт>` из valstan-writable дерева. Заявленный барьер `NoNewPrivileges=yes` в юните улья — свойство процесса, а не граница.
**Опровергнуто скептиком:** механизм «существующий приватный ssh-ключ авторизован на бокс» (ключ от другого хоста, в `authorized_keys` его нет) — путь дешевле и через user-менеджер.
**Требует владельца:** снять `NOPASSWD` (или сузить до конкретных root-owned путей), root-owned копии скриптов, `Cmnd_Alias` вместо свободных `cp`/`psql`.

### MEDIUM

**M-1. Черновики `Projects`/`Events`/`Services` уезжали в публичный REST** (unauth-external; три коллекции).
`drafts: true` + `read: anyone`: фильтра по `_status` не было, а Payload отдаёт документы со статусом `draft`, если access не режет (у `Pages`/`Posts` фильтр был — отсюда и разница).
**Вылечено:** `authenticatedOrPublished` в трёх коллекциях + инвариант-тест «черновики не отдаются публично».

**M-2. Дерево деплоя = root** (infra + скептик; часть лечится в PR 2).
Подмена tracked-файла в рабочем дереве на боксе **переживает** `git pull --ff-only` (воспроизведено в изолированном тестовом репозитории: pull exit 0, файл остался подменённым), гейт `EXPECTED_SHA` сверяет коммит, а не содержимое, «грязное дерево» печатает `::warning::` и слепо к `--untracked-files=no`, после чего из того же дерева идёт `sudo cp` юнитов и `sudo systemctl restart`, а также `sudo <скрипт>`.
**Severity пересчитана скептиком:** как **независимая** эскалация — medium (H-6 даёт тот же root дешевле), но **high сразу после закрытия H-6** — значит закрывать надо вместе, иначе фикс sudo косметический.
**Лечение:** PR 2 — восстановление дерева (`git checkout -- .` + чистка) непосредственно перед root-шагами, проверка происхождения события `workflow_run`, root-owned копия скрипта секретов; полный фикс — у владельца (H-6).

**M-3. `yandex*`-поля медиа: публичное чтение и запись мимо владельца** (authed-insider; `web/src/collections/Media.ts`).
`admin.readOnly` — только UI-флаг: публичный REST отдавал `yandexPublicUrl` (прямая ссылка на Диск в обход нашего прокси), а `PATCH /api/media/:id` позволял подставить в `yandexPath` **чужой** путь и удалить свою запись — `afterDelete` стирает файл на Диске по этому пути `permanently: true`, то есть пропадал файл чужой публикации (редактор получал инфраструктурное действие).
**Вылечено:** field-access `read/create/update` = персонал; внутренние операции (синк, прокси файла) читают/пишут через Local API с `overrideAccess: true` — проверено по всем вызовам.

**M-4. Публичная запись заказов и заявок без серверных предохранителей** (rogue-client; `Orders`, `Bookings`).
`Orders`: `create: anyone` при том, что заказы в приложении не создаёт ни один маршрут (проверено поиском) — аноним мог наполнить очередь поддельными заказами с произвольной суммой и статусом оплаты. `Bookings`: лимит и принудительный `status: 'new'` стояли **только в маршруте** `/api/bookings`, поэтому прямой `POST /api/bookings` в REST/GraphQL их обходил.
**Вылечено:** `Orders.create` → `adminOrManager`; у `Bookings` предохранители переехали в `beforeValidate` коллекции (лимит по IP — **отдельным ключом** от лимита маршрута, чтобы честный путь не расходовал счётчик дважды + принудительный `status: 'new'`).

**M-5. Журнал прод-сервиса уезжает в публичные логи CI** (supply-chain-ci; `.github/workflows/deploy-prod.yml`).
Шаг с `journalctl -u gonba` печатает хвост журнала в лог прогона, который читается всеми (репозиторий публичный). Значения секретов внедрены в env, но журнал — канал recon-поверхности (класс письма Мозга от 29.08). **Требует окна:** сокращение/маскирование дампа (не в этом PR, чтобы не менять деплой дважды за один заход).

**M-6. `push: true` у прод-адаптера БД** (адверсариальный контроль; `web/src/payload.config.ts`).
Схема может правиться drizzle'ом в push-режиме. Гвардом служит `NODE_ENV !== 'production'` в `db-postgres/dist/connect.js` (проверено по вендорскому коду) — то есть защита есть, но она **одна** и живёт во внешней библиотеке. **Не вылечено:** предложение — явный `push: false` при `NODE_ENV=production` в нашем конфиге (отдельная правка, чтобы не менять поведение прод-схемы в этом же PR).

### LOW

**L-1. `next@15.5.27` вне peer-диапазона `@payloadcms/next`** (supply-chain-ci) — `npm ls` показывает `invalid`; на работу влияет неизвестно как, но это шум, который скрывает настоящие ошибки зависимостей. Решение — согласовать версии отдельным PR.

**L-3. Политика улья разошлась с гит-близнецом.** Живой `~/.config/opencode/opencode.json` (правка 18.10, 12:15) содержит пять deny-правил (`npx tsc`, `npm run typecheck/lint/build`, `npm --prefix * run build`), которых нет в `deploy/opencode/opencode.json`. Автоматики, копирующей близнеца на бокс, нет — значит расхождение переживает любую сверку, а близнец читается как «актуальная политика». Синхронизировано в этом PR.

**L-4. Проверка записи не проверяет файл, который запись удаляет** — формулировка класса, а не отдельная дыра: H-1, M-3 и (в части плагинов) H-3 — три разных места одной ошибки «проверили владельца записи, не проверили цель действия». Кандидат на переносимую идею Мозгу (§7).

## 4. Что опровергнуто (и почему это важнее, чем выглядит)

| Кандидат | Чем снят |
|---|---|
| Поисковый индекс индексирует черновики (`data-at-rest`) | Вендорный код: `syncDrafts: false`, `deleteDrafts: true` — черновики в индекс не попадают |
| Утечка ПДн через `?depth=`-популяцию (`authed-insider`) | Популяция связей идёт с `overrideAccess: Boolean(overrideAccess)` — `adminOrSelf` для `Users` применяется |
| Path traversal через `Media.filename` | `sanitizeUploadData` бросает `Invalid filename.` и на create, и на update |
| `update` form-submissions для подмены адресатов | У плагина `update: () => false` — вектор переехал на коллекцию `forms` (учтён в H-3) |
| Массовое присваивание `data: body` | Ни в одном маршруте/эндпоинте не найдено |
| `overrideAccess` в `/api/media/replace` | Границы соблюдены (`homeCarousel` — adminOrManager, `vkImportQueue` — adminOnly) |
| Существующий приватный ssh-ключ открывает путь к root | Ключ не в `authorized_keys`, ведёт на другой хост; `known_hosts` не содержит ни одного имени этого бокса — **механизм ложный**, путь к root подтверждён другим способом (H-6) |
| `/proc/*/mem` и корки как канал секретов | `yama=1`, core limit 0 — закрыто; секреты берутся из `environ` (H-5) |
| «Агент физически не может получить root» (записано в плане и `PROJECT.md`) | Комментарий в юните описывает эффект **внутри** cgroup, а не отсутствие пути (H-6) |

Отдельно: **два кандидата скептик не снял, но переопределил** — «дерево деплоя» (medium вместо high, с условием «станет high после закрытия H-6») и «улей читает секреты» (подтверждено с поправкой: канал `environ`, а не `mem`). Это ожидаемая работа опровергателя: менять формулировку и вес, а не выкидывать класс.

## 5. Слепые зоны этого аудита (чего он не доказывает)

1. **Живых эксплуатаций не было ни одной.** Все пути выведены статически; где нужна проба — помечено «needs_live_probe».
2. **GraphQL-поверхность целиком не проходилась** (те же access-контролы ядра, но отдельной ревизии не было).
3. **Служебные таблицы Payload** (`payload-preferences`, `-locked-documents`, `-jobs`, `-migrations`), **`_v`-таблицы** и generic `versions`-эндпойнт — выборочно.
4. **nginx-конфигурация бокса не читалась**: часть выводов про IP-заголовки и проксирование остаётся на уровне «наша схема — один прокси» (проверено только то, что видно из приложения).
5. **CSRF/CORS-тонкости, WebSocket/SSE, VK-импорт как внешний вход, электронная почта** — вне измерений.
6. **Два измерения утратили сырые перечни** (§1.1) — по ним возможна неполнота списка, хотя счёт кандидатов сохранён.
7. **Отчёт не доказывает отсутствие находок вне шести выбранных измерений** — «не проверено» здесь означает именно «не проверено», а не «чисто» (#293).

**В этом PR (правки приложения + тесты + отчёт):** H-1, H-2, H-3, H-4, M-1, M-3, M-4, L-3; инвариант-тесты на два системных класса (черновики; «персонал, а не просто аутентификация») + юнит-тесты на извлечение IP и отбор ключей к удалению.

**Не проверено и не закрыто:** §5 целиком.

## 7. Переносимые уроки (кандидаты в `mailbox/to-brain/`)

1. **«Проверили владельца записи — не проверили цель действия»**: три разные находки одного класса (удаление UGC-ключа, `yandexPath`, дефолты плагинов). Обобщение: у любой операции «удалить/перезаписать по ссылке из своей сущности» нужно спрашивать «а не ссылается ли на это кто-то ещё», иначе авторизация записи не защищает объект.
2. **«Аутентифицирован ≠ персонал» в дефолтах фреймворка**: и наши хуки, и вендорные плагины читали `req.user` как признак доверия. Класс ловится **инвариант-тестом по исходникам**, а не ревью — поэтому тест заведён.
3. **Опровергатель обязан менять вес, а не выкидывать класс**: обе крупные infra-находки вернулись с «механизм иной, severity другая» — и это правильный исход, потому что «снять находку» здесь означало бы потерять путь.
4. **Артефакты многоагентного прогона не живут в `/tmp`** — смена сессии уносит их вместе с каталогом; отчёт без покрытия становится нулём, неотличимым от чистого результата.
