## Следующий шаг

**Починить курсор `lastSyncedPostId` — это мина, которая блокирует всё остальное.**

Сейчас курсор пишется **только на пути «пост создан»** — `web/src/server/integrations/vk-auto-sync.ts:588` и `:657`, — а `selectNextVkPost` (`:187`) берёт **один** пост за прогон. Значит первый же отказ классификатора **запирает источник навсегда**: каждый следующий прогон снова выбирает тот же пост, снова платно дёргает модель, снова отказывает. Пока запрет не включён, мина не взведена — но включать запрет до неё нельзя.

Нужно: перебор кандидатов **внутри** прогона и курсор по последнему **рассмотренному**, а не по последнему созданному.

Порядок — тест **красный до фикса**, потом фикс:

```bash
# тесты классификатора и отбора уже есть, туда и дописывать:
#   web/tests/int/vk-classifier.int.spec.ts
#   web/tests/int/vk-post-selection.int.spec.ts
corepack pnpm -C web run test:int
```

⚠️ На PC79 нет `node_modules` — сначала `npm ci` в `web/` (проект давно на npm, см. техдолг про `corepack pnpm` в доках).

**Дальше по порядку** (не перепрыгивать): фикс курсора → разметка владельцем ~30 спорных постов → глобал `vkEditorialRules` → и только потом запрет, **начиная с одного источника**. Первым включать **без запрета**: вердикт только в журнал, пост публикуется как сейчас.

## Failed approaches (этой нитки)

- **Считать nginx-инцидент закрытым по внешнему замеру** — снаружи все шесть доменов отдавали свой контент ещё до начала работ, и соблазн был закрыть мандат этим. Не годится: внешний замер показывает результат, но не причину, а причина решала, вернётся инцидент или нет. **Не повторять:** приёмка «снаружи зелено» не заменяет разбора на боксе.
- **Принять фильтр маскировки по рассуждению** — первая версия «выглядела правильной» и содержала **две** ошибки, которые нашлись только прогоном настоящих команд: порядок `sed` (короткое имя — префикс FQDN, замена оставляла хвост хостера) и граница действия фильтра (чистит stdout удалённой команды, но не сообщения ssh-клиента). **Не повторять:** фильтр вывода принимается прогоном по настоящему выводу с пустым грепом — и с контролем, что вывод непустой.
- **Засчитать за приёмку прогон, исполнявший старую версию артефакта** — упавший деплой `33329973163` дал бы «0 вхождений» просто потому, что раннер маскирует значения только тех секретов, на которые workflow **ссылается**, а та версия не ссылалась. **Не повторять:** приёмка обязана исполнять ту версию, которую проверяет.
- **Мержить следующий PR по зелёному CI предыдущего** — так и уронил деплой #211. Деплой стартует от **завершения CI**, а не от мержа; окно в минуты. **Не повторять:** ждать `completed` предыдущего деплоя. Записано в `AGENTS.md → Сериализация деплоев`.
