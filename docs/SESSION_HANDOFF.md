## Failed approaches (этой сессии)

- **`npm audit fix --omit=dev`** — флаг не только фильтрует отчёт, он **подрезает дерево**: снёс все devDependencies вместе с TypeScript, и следующий `tsc` упал с «No such file or directory». Лечится обычным `npm install`, но выглядит как поломка обновления. Для отчёта использовать `npm audit --omit=dev` (чтение безопасно), для починки — `npm audit fix` без флага.
- **Грепать версию Payload в standalone-бандле** — её там нет ни строкой: пакет вкомпилирован в чанки Next, `node_modules` бандла содержит 43 пакета и `payload` среди них отсутствует. Версию снимать с дерева на боксе.
- **Считать грабли из письма подтверждёнными без проверки** — предупреждение про `next-env.d.ts` описывало поломку `tsc`, которой у нас нет (`skipLibCheck: true` + `.next/types/**/*.ts` уже в `include`). Дописывание строки реально, краснота — нет. Проверять, а не переносить вывод.
- **Первый `navigate` по punycode вручную** — набрал не тот (`xn--80ahihmi` вместо `xn--80abf4be9f`), получил отказ навигации. Отдавать инструменту кириллический домен как есть.
- **Монитор деплоя по `headSha`** — отработал вхолостую: squash-merge дал на `main` SHA, с которым сравнение не сошлось, и цикл молча докрутил до конца. Статус пришлось снимать вручную. Сверять по `status=completed` + времени, а не по ожидаемому SHA.

## Не забыть (low-priority)

- **`jobs.access.run` пускает любого залогиненного без проверки роли** — новый пункт backlog, кандидат в #015.
- **`next lint` deprecated, исчезнет в Next 16** — CI зовёт именно его.
- **На боксе юнит `gonba-media-cache` зовёт `corepack pnpm`**, а дерево теперь npm; `package.json` держит `packageManager: pnpm@10.15.0` и блок `pnpm.onlyBuiltDependencies`, в репо лежит устаревающий `pnpm-lock.yaml`. Решить осознанно в одну сторону.
- **`last_error` не чистится при успехе** — виден на двух источниках (id 6 и 7).
- **Источник `eco-hotel-booking` (id 6)** — по-прежнему ждёт шага владельца.

- **npm на Windows берёт cmd.exe** — звать `./node_modules/.bin/<бинарь>` из git-bash.
