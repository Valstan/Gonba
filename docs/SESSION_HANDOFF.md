## Текущая нитка

**Правила редакции для VK-классификатора.** За эту сессию нитка продвинулась от «предусловие закрыто» до «правила живут на проде»: снята мина курсора, владелец разметил 30 спорных записей, правила выведены **из его разметки** и проверены по ней, глобал `vkEditorialRules` построен, задеплоен и наполнен. Осталось увидеть правила в бою и только потом включать запрет.

## Следующий шаг

**Снять приёмку первого живого прогона классификатора с правилами.** Таймер VK бьёт каждые 3 ч (гард интервала съедает каждый второй прогон), первый прогон после наполнения глобала — 01.09 21:02 MSK, то есть к следующей сессии он уже был.

Смотреть надо не «прогон зелёный», а **что именно решила модель**:

```bash
# вердикты последних записей: провайдер, модель, обоснование
ssh GONBA 'set -a; . /etc/gonba/gonba.env; set +a; psql "$DATABASE_URL" -c "
  SELECT id, left(title,50) AS title,
         vk_classification->>'"'"'provider'"'"' AS provider,
         vk_classification->>'"'"'projectSlugs'"'"' AS projects,
         left(vk_classification->>'"'"'rationale'"'"', 90) AS rationale
  FROM posts WHERE vk_classification IS NOT NULL
  ORDER BY id DESC LIMIT 5;"'
```

Проверяемая гипотеза одна и конкретная: **записи из общей группы села должны перестать оседать на `gonba`** — по разметке владельца туда относится примерно одна из девятнадцати, остальные уходят в «Сельский туризм», «Оленью ферму», «Гостевые домики» и «Лепоту».

**Дальше по порядку** (не перепрыгивать): приёмка прогона → при расхождениях править **текст правил в админке**, а не код (в этом и был смысл глобала) → и только потом **запрет**, начиная с одного источника и сперва «вердикт только в журнал, пост публикуется как сейчас».

## Failed approaches (этой нитки)

- **Двигать курсор на любой ошибке импорта** — напрашивалось как лечение мины и звучало просто. Отклонено на этапе разбора: разовый сетевой сбой или блип БД **молча съел бы годную запись** — на публичном сайте её бы просто не было, и никто бы не узнал. Взято ограниченное число попыток (`VK_MAX_IMPORT_ATTEMPTS = 3`) с перешагиванием на выборе. **Не повторять** формулировку «курсор по последнему рассмотренному» без оговорки про потерю записей.
- **Заводить отдельный проект под пасеку и «Медовую тропу»** — 16 записей из 99, и своего проекта у темы не было; я предлагал это как вероятный исход и дал в разметке отдельную кнопку «ни один не подходит». **Владелец кнопкой не воспользовался ни разу** и отправил все записи в «Сельский туризм». Вопрос закрыт фактом, а не мнением.
- **Считать ручной `workflow_dispatch` нормальной ценой миграции** — так было записано в процедуре, и я предъявил владельцу список из четырёх шагов. Он ответил «слишком сложно», и был прав: гейт проверял **признак** (новый файл в коммите) вместо охраняемого свойства (схема прода не отстала). **Не повторять:** прежде чем выдавать пользователю ручной шаг, спросить, что именно измеряет гейт, который этот шаг требует.
- **Ключевые слова как классификатор** — эвристика по корням слов писалась ТОЛЬКО для отбора кандидатов на разметку и годится лишь на это. На проверке правил она дважды соврала (`мед` внутри «**Меди**а»), и оба раза это выглядело как содержательное расхождение с владельцем. **Не повторять:** короткий корень проверять по границе слова с ОБЕИХ сторон, левой мало.

## Не забыть (low-priority)

- **Отказ измерителя за сессию трижды выглядел как отказ измеряемого** (класс #252, письмо brain 31.08): клиент не смог проверить отзыв сертификата → три сайта показались лежащими; `diff` пометил все 18 строк схемы как расходящиеся из-за CRLF против LF; **зелёный CI относился к предыдущему коммиту**, а не к текущему — последнее едва не стоило мержа не той версии. Прежде чем верить в поломку — спросить, чем мерил.
- **Разовый tsx-скрипт на проде поднимает drizzle в push-режиме** — заведено в `PENDING_FOLLOWUPS`. В этот раз обошлось (схема совпала, 0 расхождений на 1152 колонках), но скрипт из ветки с новым полем применил бы схему в обход миграции и гейта.
- **На этой машине (PC79) теперь есть локальная БД `gonba`** — поднята из схемы прода (без данных) ради генерации и сверки миграции; базовая линия миграций засеяна одним батчем, на проде батчи инкрементные. Номер batch для прода брать из БД (`max(batch) + 1`), а не из локальной копии.
- **`npm run test:int` на Windows не запускается** — скрипт зовёт `corepack pnpm`, которого нет на PATH; звать `test:int:raw` напрямую с `--script-shell` на git-bash. Два int-теста падают локально по причинам окружения, в CI зелёные — оба записаны в `PENDING_FOLLOWUPS`, чинить здоровый код не надо.
- **Гард интервала съедает каждый второй прогон VK-синхронизации** — требует выбора из трёх лечений, не слепой правки.
- **Доля пустых ответов DeepSeek не измерена** — мерить до починки, не оптимизировать неизмеренное.
- **Сетевой путь до бокса отсюда деградирован** — внешние замеры задержки с этой машины недостоверны; контент при этом приходит верный.
