## Текущая нитка

Сессия — **возврат улья OpenCode на бокс по слову владельца «как на испанском»**: движок в браузере, свой ВПН с подпиской и сменой серверов, набор ярлыков на рабочем столе. Одним PR [#323](https://github.com/Valstan/Gonba/pull/323): `deploy/neural/` (xray + разбор подписки NextGenVPN + смена сервера с fail-closed сверкой HTTP-инбаунда), `HTTPS_PROXY` в юните `opencode-web` (nft-redirect по uid здесь **нельзя** — движок и сайт под одним `valstan`), `scripts/gonba-kit/` (7 ярлыков + диспетчер), идемпотентная установка в `deploy-prod.yml`. Вторым PR [#324](https://github.com/Valstan/Gonba/pull/324) закрыт последний ручной шаг установки: конфиг движка (`deploy/opencode/opencode.json`) теперь тоже ставит деплой.

**Главная находка сессии — не про ВПН, а про доставку команды.** `Start-Process -ArgumentList` (массив) склеивает командную строку **без кавычек**, а `ssh.exe` разбирает её заново: `sudo -n bash -c 'systemctl start opencode-web'` доезжало как `sudo -n bash -c systemctl start opencode-web` — bash запускал голый `systemctl`, тот печатал список юнитов и выходил с **0**. Снаружи это «успешный запуск» службы, которую никто не запускал: 45 с ожидания и «движок не поднялся». Коварство: `systemctl stop …` кавычек не требует и работал, поэтому половина действий была зелёной. Лечение — тело команды едет base64-строкой (`echo <b64> | base64 -d | bash`). Вторая мелочь того же рода: `systemctl is-active` возвращает **3** на неактивном юните, и маркер `OC_DONE:$?` честно приносил 3 — «доктор» ругался на связи там, где связь живая (нужен `|| true`).
