# 0008. Проектные миры и неглубокая навигация

- **Status:** Accepted
- **Date:** 2026-08-04
- **Deciders:** владелец GONBA, Codex

## Context

Проекты были представлены орбитой и каталогом, после которых пользователь попадал на обзор проекта, а затем ещё раз переходил в новости, галерею, лавку или контакты. Обзор повторял сокращённые версии этих блоков и воспринимался как промежуточная страница. Переключение между проектами требовало возврата на главную или в каталог.

Единая карточная система различала проекты в основном цветом и SVG-мотивом. Этого недостаточно для ощущения самостоятельного места, особенно когда несколько проектов используют одинаковую структуру контента.

## Decision

Сделать каждый проект самостоятельным «миром» внутри общей оболочки сайта: прямой вход с главной, постоянный переключатель проектов, не более одного уровня разделов внутри проекта и тематический арт-профиль из палитры, generated background, реальных фотографий и декоративного мотива.

Маршруты разделов сохраняются для совместимости и SEO, но интерфейс больше не строит из них последовательную воронку. `/projects/<slug>` становится полноценным обзором, а не предпросмотром.

## Alternatives considered

- **Оставить орбиту и только освежить CSS** — сохраняет трудное прицеливание, слабую семантику карточек и возврат через главную для смены проекта.
- **Слить все разделы в один огромный документ** — уменьшает URL-глубину, но ухудшает загрузку, сканирование и прямые ссылки.
- **Дать каждому проекту полностью отдельный шаблон** — максимум индивидуальности, но дорого поддерживать и легко получить функциональный дрейф.

## Consequences

### Положительные

- Любой проект и его основной раздел доступны за 1–2 действия.
- Переключение проектов не выбрасывает пользователя из проектного контекста.
- Проекты визуально различимы, но используют одну доступную и поддерживаемую систему.
- Старые ссылки продолжают работать.

### Отрицательные

- Четыре растровых фоновых полотна увеличивают бюджет статических assets примерно на 1 МБ до оптимизации/CDN-кэширования.
- Project layout делает запрос списка проектов для переключателя.

### Нейтральные

- Орбитные компоненты и legacy-global временно остаются в коде для безопасного отката; после стабилизации их следует удалить отдельным deadcode-PR.
