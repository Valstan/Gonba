# Почему очередь стояла

Письма показывались в `/start`, но не превращались в обязательный рабочий план: сессии продолжали свежий handoff и явную пользовательскую нитку. Это дефект контура приоритизации. В `AGENTS.md` добавлено правило: незакрытый `high MUST` автоматически становится первым пунктом плана; отложить его можно только с причиной и триггером возврата в исходящем письме.

# Quarterly self-audit: предложения владельцу

## Рефакторинг

1. **Снять over-export без переписывания модулей** — 55 values + 20 types, партиями по доменам с typecheck/test после каждой. Стоимость: 2–4 часа; эффект: меньше случайного API и точнее следующие dead-code отчёты.
2. **Дочистить legacy Project World / старую главную** после подтверждения отсутствия rollback-нужды. Стоимость: 2–3 часа; эффект: меньше параллельных UI-моделей и CSS-наследия.
3. **Оформить операционные CLI как явный каталог runbook-команд** (`package.json` scripts + owner/purpose), затем удалить действительно одноразовые. Стоимость: 1–2 часа; эффект: knip не путает runtime entry с мусором, запуск воспроизводим.

## Функциональность

1. **Диагностика VK auto-sync в админке:** источник → проект/категория, lastSyncedPostId, последний успех/ошибка, безопасный preview следующего импорта. Стоимость: 1–2 дня; снижает риск неверных привязок, найденный последним аудитом.
2. **Контентный health-dashboard:** пустые контакты, заглушки, отсутствующие изображения, draft/published несогласованности, сломанные связи. Стоимость: 2–3 дня; превращает ручной визуальный аудит в повторяемый контроль.
3. **Минимальная панель продуктовой аналитики:** статусы Метрики/LiveInternet, основные события и ссылки на кабинеты без хранения секретов. Стоимость: 0.5–1 день после регистрации счётчиков.
