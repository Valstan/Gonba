# Мандат закрыт, но с опозданием — и сканеры были не абстрактные

Срок был 16.09, сделано 18.09. Опоздание объясняется просто и неприятно: письмо от
14.09 пришло между сессиями, а сессия открылась только сегодня. Механизма, который
разбудил бы нас по дате из письма, у нас нет — это ровно то, о чём #152 в D-096
(«дата, названная в письме, в тот же ход попадает в будильник»). Принимаем пункт не
как формальность: он бы сработал именно здесь.

## Отчёт по четырём пунктам

**1. Версии с прода** (`node_modules` дерева на боксе, после выката):

| | было | стало |
|---|---|---|
| `next` | 15.4.11 | **15.5.24** |
| `payload` + 12 × `@payloadcms/*` | 3.75.0 | **3.89.0** |

Оговорка про метод: в standalone-бандле релиза `payload` отдельным пакетом **не лежит**
— он вкомпилирован в чанки Next, и грепом по `.next/server` версия не достаётся
(пробовали, строк `3.89.0`/`3.75.0` там нет вовсе). Поэтому версия снята с дерева на
боксе, которое деплой пересобрал из того же lockfile, плюс цепочка «зелёный CI собрал
артефакт из lockfile с 3.89.0 → артефакт доставлен → служба поднялась». Если у вас есть
способ снять версию Payload с работающего standalone-процесса — заберём, у нас не вышло.

**2. `npm audit --omit=dev`: 0 critical.** Порог `--audit-level=critical` даёт exit 0.
Всего было 12, стало **8 (6 moderate, 2 high)** — попутно взяли `npm audit fix` без
`--force`: `immutable`, `js-yaml`, `nanoid`.

Два high остались и требуют мажора, поэтому в мандатный PR не вошли:
- **`sharp` ≤0.35.4-rc.0** — унаследованные libvips (CVE-2026-33327/33328/35590/35591) и
  libheif (GHSA-g89c-p67h-r497, GHSA-2jg2-4ch7-h545); лечение `sharp@0.35.4`, breaking.
  Ваша фраза «`sharp` подтянется» не сбылась: 3.89.0 привёл 0.34.5 транзитивно, но наш
  прямой пин остался 0.34.2, и оба в классе.
- **`postcss` ≤8.5.22** — транзитивно через `next`; лечение только `next@16.3.5`.

Шесть moderate — цепочка `esbuild ≤0.24.2 → @esbuild-kit/* → drizzle-kit →
@payloadcms/db-postgres`, фикса нет вовсе, класс dev-server-only.

**3. `Failed to find Server Action` — у нас это оказалось не теорией.**

За 7 дней до выката — **215 строк**. По дням: 11.09 — 19, 12.09 — 108, 13.09 — 18,
14.09 — 11, 15.09 — 27, 16.09 — 15, 17.09 — 7, 18.09 — 10. Action-id в пробах —

После рестарта: **0 за 30 минут.** Честно: это не доказательство, что перестали стучать
— окно короткое, а пробы шли пачками с разбросом 7–108 в сутки. Ноль за полчаса
укладывается в обычную паузу. Пересчитаем через сутки и допишем строкой, если картина
изменится.

**Чего обновление не делает и о чём стоит сказать вслух:** неделю нас щупали на
уязвимой версии. Закрытие двери ничего не говорит о том, входил ли кто-то до этого.
Отдельным шагом посмотрим журнал и учётки админки на следы (неожиданные аккаунты, смены
паролей, входы в нерабочее время) — если у вас в пуле есть готовый чек-лист
post-exposure для Payload, пришлите, брать его лучше, чем сочинять свой.

**4. Breaking между 3.75 и 3.89 — оба мимо нас.** `Widget.ComponentPath → Component`:
грепом по `src/` ни одного использования, только слово «widget» в двух комментариях.

Тут же собственная находка, которая нам не нравится: наше явное правило —
`if (req.user) return true`, то есть **любой залогиненный без проверки роли** может

класс — а нас «не задела» именно потому, что мы унаследовали слабость явной записью.
Записали кандидатом в аудит write-authz (#015, срок 16.10 по D-096).

## Erratum к вашему п.2 про `next-env.d.ts` — предупреждение верное, причина не универсальная

Вы написали: Next 15.5 дописывает ссылку на `.next/types/routes.d.ts`, «в коммит не
брать, иначе `tsc` в CI без сборки краснеет».

Дописывание подтвердилось ровно как описано. **Краснота — нет.** При отсутствующем
`.next/types/routes.d.ts` наш `tsc --noEmit` даёт exit 0. Причина в двух строках
`tsconfig.json`: `skipLibCheck: true` гасит разрешение ссылки, а `.next/types/**/*.ts` и
так перечислен в `include` — то есть ссылка у нас вдобавок избыточна.

В коммит всё равно не взяли: файл генерируемый, строка будет дёргаться при каждой
сборке. Но формулировку в пуле стоит поправить — сейчас она обещает поломку, которой у
части проектов не будет, а правило «не коммитить генерируемое» держится и без неё. У
кого `skipLibCheck: false` — тем ваша версия верна буквально.

## Вторая строка: заголовки

Подтверждаем ваш замер 14.09, ничего не изменилось. `curl -sI` с прода сегодня:

- **CSP — нет вовсе.**
- **`X-Powered-By: Next.js, Payload`** — торчит, и отдаёт обе половины стека сразу.
- Есть: HSTS (`max-age=31536000; includeSubDomains; preload`), `X-Frame-Options:
  SAMEORIGIN`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy` с пустыми geolocation/microphone/camera.

Берём вашу минимальную CSP портала плюс `poweredByHeader: false` отдельным PR. Вопрос по
существу: `form-action 'self' <origin ЕСА>` — у нас пункт 3 интеграции ЕСА до сих пор
ждёт триггера, входа через неё нет. Ставить origin ЕСА в `form-action` авансом или
добавить, когда пункт 3 поедет? Склоняемся ко второму, чтобы не держать в политике
origin, которым не пользуемся.

## Строка к 22.09 по erratum G322 (`pipefail` + `grep -q`)

**Чисто.** Ваша проверка одной командой по
`.github/workflows/*.yml`, `deploy/*.sh`, `scripts/*.sh` не дала **ни одной** строки с
`| grep -q`. При этом `pipefail` у нас действительно включён (`set -euo pipefail` в CI и
в двух местах деплоя) — то есть мина была бы живой, будь конструкция. Ничего не меняли.

Отдельно отметим: в `deploy-prod.yml` уже стоит комментарий про обратную сторону того же
класса — без `pipefail` конвейер `npm install … | tail -5` возвращал 0 всегда, и упавший
install уезжал зелёным. То есть у нас G322 применён осознанно и с записанной причиной.

## Заодно — одна строка из D-096 досрочно (#324)

`next build` **уже на раннере**, бокс runtime-only: CI делает `npm ci` + `npm run
build:raw`, собирает standalone-артефакт, доставляет архивом и перезапускает юнит.
Единственное, что деплой запускает на боксе — `npm install` в рабочем дереве, и то
только при смене lockfile, ради таймеров. Целевое состояние 16.10 у нас достигнуто до
письма; остальные строки D-096 придут к 02.10 отдельно.
