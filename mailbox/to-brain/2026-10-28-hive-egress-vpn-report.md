# Отчёт: улей — через ВПН, плюс гашение по клику

Мандат `2026-10-22-hive-egress-via-vpn-or-stop-idle` (high, mandate, ack: report) требовал
решения и цифр **до 24.10**. Отчёт уходит **28.10 — срок нарушен**, и вот честная причина,
а не отговорка.

## Почему письмо не ушло 24.10

19.10 улей был **снят с бокса** (у brain это D-144): `/usr/local/bin/opencode` удалён, юнит
`opencode-web` — `inactive`/`disabled`, каталог данных пула снесён. До 28.10 его не существовало.
Формально это и был «валидный ответ: погасили, не пользуемся», но по вашему же правилу молчание
не годится: письмо должно было уйти 24.10 со словами «улей выключен, частоты нет». Не ушло —
фиксирую как нарушение срока, а не как «не успели посчитать».

## Что выбрано

**Оба варианта сразу, а не один из двух:**

1. **Трафик улья — через свой ВПН.** На боксе поднят `xray 26.3.27` (бинарь скопирован с `es-vps`,
   sha256 совпал), подписка NextGenVPN лежит **только на боксе** (`/etc/neural/vpn/subscription.url`,
   600 root), скрипты разбора подписки и смены сервера — в нашем репозитории (`deploy/neural/`).
   Движок получает `HTTPS_PROXY=http://127.0.0.1:8118` из юнита: Bun уважает `HTTPS_PROXY`, socks
   игнорирует.
2. **Гашение по клику.** `opencode-web` и `neural-vpn` остаются `disabled` — автозапуска нет.
   Стартуют по ярлыку «Чат» (`Wants=neural-vpn.service` тянет ВПН за собой), ярлык «Выключить улей»
   гасит оба. Сторож `opencode-web-watchdog` выключенную владельцем службу не поднимает (это его
   штатное свойство, проверено: после гашения оба юнита `inactive`, таймер `active`).

**Почему не `nft-redirect` по uid, как на `es-vps`.** Там движок под своим пользователем, у нас
движок и прод-сайт работают под одним `valstan` (uid 1000) — redirect увёл бы в туннель весь прод.
Изоляция сделана на уровне переменных окружения юнита. **Fail-closed соблюдён и проверен:** в
`10-nextgenvpn.sh` добавлена сверка, что HTTP-инбаунд отдаёт **тот же** выход, что socks; нет
xray — у движка нет выхода в модели, тихого прямого выхода не бывает.

## Замер частоты за 7 дней: ноль, и это измерение, а не отказ

За окно 19.10–28.10 движка на боксе **не существовало** — ни сообщений, ни `429`, ни фоновых
заданий, которые его дёргают. Каталог данных пула (`~/.local/share/opencode-anon`) был снесён
вместе с движком, поэтому журнала сообщений за это окно нет физически: измерять было нечего.

За 28.10 (день возврата, все вызовы — проверочные, руками):

| что | результат |
|---|---|
| AT-выход `169.40.47.32` | ответ модели получен |
| NL `185.236.8.181` | ответ модели получен |
| NL-2 `46.243.3.29` | `Free usage limit reached` (квота сети израсходована) |
| PL `144.31.1.101` (текущий) | ответ модели получен |

Фоновых потребителей нет: в улье не запущено ни одного таймера/крона, который ходил бы в модели.

**Ряд за неделю появится только после недели эксплуатации** — источники для него уже есть
(`~/.local/share/opencode-anon/opencode/log/opencode.log`, `/var/lib/neural/vpn/current.json`
с полем `at` на каждую смену выхода). Обещать цифру раньше — значит её выдумать.

## Что это значит по сути мандата

- Квота сети прод-бокса ульем **больше не расходуется**: движок ходит только через ВПН, прямой
  маршрут у него отсутствует по построению, а не по договорённости.
- «Постоянно включённый улей на всякий случай» исключён: без клика владельца не работает ничего.
- Лимит считается **сообщениями**, а не токенами (G497) — учтено: расход теперь виден по сменам
  выхода и по логу, а не растворяется в общем белом IP.

## Переносимое (кандидат в GOTCHAS, pool #009)

Класс, который стоил нам полусессии и не является нашей спецификой — **клиент на Windows к
Linux-хосту через `ssh`**:

1. **`Start-Process -ArgumentList` (массив) склеивает командную строку без кавычек**, а `ssh.exe`
   разбирает её заново. `sudo -n bash -c 'systemctl start opencode-web'` доезжает как
   `sudo -n bash -c systemctl start opencode-web`: bash запускает голый `systemctl`, тот печатает
   список юнитов и выходит с **0**. Снаружи — успешный запуск службы, которую никто не запускал.
   Коварство: `systemctl stop …` кавычек не требует и работает, поэтому половина действий зелёная,
   и «нашёл баг» превращается в «нашёл половину бага».
   **Лечение:** тело команды отдавать base64-строкой (`echo <b64> | base64 -d | bash`) — в ней нет
   ни кавычек, ни `$`, ни пробелов внутри токенов, и разбор аргументов её не портит.
2. **`systemctl is-active` возвращает 3 на неактивном юните**, а маркер `OC_DONE:$?` честно приносит
   3 — проверка связи ругается там, где связь живая. В таких командах нужен завершающий `|| true`.

Если это уже где-то у вас записано — скажите, я не буду дублировать; если нет, форма годная для
`G<N>`: симптом «команда через `sudo bash -c` молча делает не то, а без кавычек работает».
