# Задание Сарафану + сверка лимитов

Владелец просит, чтобы OpenCode-агент стоял не только у нас, но и у Сарафана — как у нас, через браузер, без терминала. Ниже блок, который **можно пересылать Сарафану почти как есть**: всё, что нужно переиспользовать, лежит в нашем публичном репозитории, поэтому копировать можно напрямую. Отдельными абзацами — то, что нужно решить **до** копирования (адаптационные точки) и грабли, которые стоили нам времени.

1. **Переслать Сарафану блок «Задание»** ниже (или сказать, если его надо оформить иначе — мы не знаем, как удобнее на его стороне).

## Задание Сарафану (пересылать как есть)

### Что получится

Веб-UI агента на боксе: работа идёт в браузере с любого компьютера владельца, пароль и ключи локальных пулов на сервере не лежат, новый публичный порт не открывается. Агент работает в **отдельном клоне** проекта, боевое дерево не трогает. Плюс «глаза» — headless Chromium, чтобы агент сам видел страницу, которую сделал.

### Порядок (наш, адаптировать имена)

```bash
# 1. бинарник: архив, без curl|bash
curl -fsSL -o /tmp/opencode-linux-x64.tar.gz \
  https://opencode.ai/update/api/latest/cli/opencode/opencode-linux-x64.tar.gz
tar -xzf /tmp/opencode-linux-x64.tar.gz -C /tmp/oc-install
sudo install -m 0755 /tmp/oc-install/opencode /usr/local/bin/opencode && opencode --version

# 2. каталоги и пароль (пароль не печатать ни в чат, ни в логи)
mkdir -p ~/.config/opencode-web ~/.local/share/opencode-anon ~/work
chmod 700 ~/.config/opencode-web
[ -s ~/.config/opencode-web/anon.env ] || \
  printf 'OPENCODE_PASSWORD=%s\n' "$(openssl rand -base64 48 | tr -d '/+=\n' | cut -c1-40)" \
  > ~/.config/opencode-web/anon.env
chmod 600 ~/.config/opencode-web/anon.env

# 3. политики, рабочий клон (НЕ боевое дерево), юниты, метёлка
mkdir -p ~/.config/opencode && cp <наш>/deploy/opencode/opencode.json ~/.config/opencode/opencode.json
[ -d ~/work/sarafan ] || git clone <свой репозиторий> ~/work/sarafan
sudo cp <наш>/scripts/opencode-tmp-sweep.sh /usr/local/bin/opencode-tmp-sweep
sudo cp <наш>/scripts/opencode-pair-link.sh /usr/local/bin/opencode-pair-link
sudo chmod 0755 /usr/local/bin/opencode-tmp-sweep /usr/local/bin/opencode-pair-link
sudo cp <наш>/deploy/systemd/opencode-web.service ~/deploy/systemd/opencode-tmp-sweep.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now opencode-web.service opencode-tmp-sweep.timer
```

### Решить до копирования (наши значения — не обязательные)

- **Каталог рабочего клона — ASCII.** У вас боевой путь `~/САРАФАН` (кириллица). Боевой не трогать вообще, а клон агента лучше завести ASCII-путём (`~/work/sarafan`): кириллица в юните, в командах агента и в `pgrep`-ах — лишний класс отказов, который нам не нужен.
- **Порт сервера.** Мы взяли `49374` (дефолт OpenCode для Linux), наружу он не смотрит: слушает `127.0.0.1`, вход — SSH-туннель + одноразовая ссылка (код 5 минут → cookie ≈30 дней). Проверьте, что порт свободен у вас, иначе берите свой; локальный порт туннеля у нас `14974`.
- **Отдельный каталог данных** `XDG_DATA_HOME=~/.local/share/opencode-anon` — это и есть «свой пул лимитов». Общий каталог с чужим агентом = общий пул.
- **Лимиты памяти — от вашего бокса.** У нас холостой сервер держит ~370 МБ, пик на прогреве ~390 МБ (замеры 17.10), и на 2 ГБ с 6 сайтами и Postgres мы поставили `MemoryHigh=500M/MemoryMax=700M`, `MemorySwapMax=0`, `Nice=5`, `CPUWeight=50`, `IOWeight=50`, `OOMScoreAdjust=200` («добрый сосед»: пусть ядро убьёт агента, а не уведёт бокс в swap). У вас Python + Celery + Redis + Postgres + ВК-бот — считайте свободное и не отдавайте агенту больше примерно трети свободного.
- **Политики — под свои секреты.** Наш файл запрещает `git push origin main|master` (все формы, включая force), `gh workflow run deploy*`, `sudo *` и чтение `/etc/gonba/*`. Вам нужно добавить своё: чтение `/etc/sarafan/*`, свои деплой-команды, свои прод-операции. Политики — жёсткий блок, снять одобрением в UI нельзя; плюс `NoNewPrivileges=yes` в юните.
- **Диск.** `opencode` + кэш + глаза: у нас браузеры Playwright заняли 681 МБ, npm-кэш ≈270 МБ, диск ушёл 78% → 80%. У вас диск уже один раз доходил до 100% — сначала посчитайте свободное, глаза ставьте вторым шагом и только если место есть.
- **Сборки на боксе не гонять.** Канон «сборка в CI» у вас свой, но смысл тот же: агент правит код в клоне и отдаёт ветку/PR, тяжёлое — не на прод-боксе.
- **Если ваш прод — тот же бокс, что наш:** второй экземпляр **не поднимать** (наш холостой держит ~370 МБ). Ходите в уже поднятый на `127.0.0.1:49374`, добавив в общие политики свои запреты и заведя свой рабочий клон. Это дешевле и безопаснее, чем второй сервер на 1 ядре.
- **Кто входит:** пароль лежит на боксе в `anon.env` (0600) и никуда не печатается; клиент у владельца забирает одноразовую ссылку и открывает браузер. Первый запуск на новом компьютере — запускатель с `-Setup` (заводит цель, порты и ключ в локальном `opencode-web.conf`, в git он не идёт).

### Грабли, за которые мы заплатили (проверено замером)

1. **`sudo apt-get install chromium` на Ubuntu 24.04 — тупик:** у пакета `chromium` кандидата нет, `chromium-browser` — snap-заглушка. Рабочий путь один: `npx -y playwright@latest install chromium` (user-local, без sudo, ноль системных изменений).
2. **Сырой Chrome в юните с `NoNewPrivileges=yes` падает `rc=134`** (abort): на Ubuntu 24.04 `kernel.apparmor_restrict_unprivileged_userns=1` запрещает песочницу пространств имён. Канонической команде `npx playwright screenshot` флаг `--no-sandbox` не нужен (идёт через `chrome-headless-shell`), а вот сырому бинарю — нужен. Мы не стали править систему.
3. **`-Check` в неинтерактивной среде доказывает не всё.** У нашего запускателя 17.10 был баг: при двойном клике из настоящей консоли `ssh` не пишет в stderr ничего, `Get-Content -Raw` на пустом файле отдаёт `$null`, и `.Trim()` по нему — исключение; в неинтерактивном прогоне тот же код был зелёным (ssh там дописывает в stderr предупреждение `GetConsoleMode`). Починено, есть регрессия `scripts/opencode-web.test.ps1`, которая подставляет реально пустой stderr в две копии — с защитой и без. **Берите запускатель с нашего `0513247` или позже.**
4. **Ваш G455 — это ровно та грабля, которую запускатель уже обходит:** ssh с ожиданием exit висит, поэтому запускатель пишет stdout/stderr в файлы, ждёт маркер `OC_DONE:<код>` и добивает ssh. Ничего не изобретайте заново.
5. **Сервер — только loopback.** Не открывать порт наружу: внутри агент с shell-доступом к общему боксу. Вход — туннель + одноразовая ссылка, пароль на боксе.
6. **ssh к боксу иногда не отвечает за 30 с — и это не ваш клиент.** Замер 17.10 на нашем боксе: `load 0.05`, но в `ss -ta state syn-recv` висело 40–60 полуоткрытых соединений к публичному IP (443/80/22) с чужих сканирующих адресов; sshd считает такие слоты «неаутентифицированными» и при превышении `MaxStartups` отбрасывает часть новых подключений. Лечим повтором в автоскриптах. Мелочь: `ss ... state syn-recv` **без `-a`** врёт (0 при фактических 40) — считать состояния только с `-a`.
7. **Модель нужна с vision.** Пул анонимный и бесплатный (`opencode/*-free`), но картинку читает только модель со «зрением» (у нас по названию такая одна — `nemotron-3.5-super-vl-free`). Скриншоты **остаются на боксе**: в письма и репозитории их не таскать.

### Приёмка (то, что мы реально мерили)

- `-Check` запускателя зелёный; регрессия `opencode-web.test.ps1` — красное→зелёное; вход с компьютера владельца по ссылке (живьём, в браузере);
- снимок страницы через глаза: `npx playwright screenshot --viewport-size=1440,900 --wait-for-timeout=5000 http://127.0.0.1:PORT shot.png` → PNG на боксе;
- замер памяти холостого сервера (`systemctl show -p MemoryCurrent,MemoryPeak opencode-web`) и метёлки `/tmp` до/после запуска (у нас: удалено 0 при `PrivateTmp=yes` — то есть общий `/tmp` не растёт).

## Зачем сверять адреса (вопрос владельца)

Пул анонимный, и лимит бесплатных моделей считается **по исходящему адресу бокса** (так это описано в вашем плейбуке). Значит:

- если у Сарафана и у нас **разные** исходящие адреса — лимиты независимы, у каждого свой «кошелёк» бесплатных токенов;
- если **один и тот же** — общий, и два агента будут выедать его друг у друга (это не ошибка установки, но знать надо заранее).

Как померить (без публикации значений):

```bash
curl -4 -s --max-time 10 https://api.ipify.org; echo   # адрес, как его видит интернет = по нему считают лимит
ip -4 -o addr show scope global                        # адрес на интерфейсе: совпал — белый, разошёлся — бокс за NAT
```

Отдельный риск, если бокс **за NAT**: у него исходящий адрес может быть общим не только с нами, но и с посторонними клиентами хостера — тогда бесплатный пул может быть уже выбран чужими, и агент будет получать отказы. Проверяется живым запросом к моделям: если стабильно 429 — это оно, и тогда честный ответ владельцу «на этом боксе бесплатный пул делится с посторонними», а не «поставили — не работает».

Наш адрес — публичный, собственный; значение передадим, как только скажете куда (в git не кладём: у нас публичный репозиторий).
