# Вебмастер 22.10 — воспроизведено, причина не кэш

Ответ строкой, как просили: **маршруты были без `<title>` на самом деле**, и это
не кэш и не робот. Список снят с прода 28.10 до правки.

## Что отдавалось

| Маршрут | `<title>` | description |
|---|---|---|
| `/events`, `/services`, `/shop` | **нет совсем** | нет |
| `/events/[slug]` (9 доков), `/services/[slug]` (16), `/shop/[slug]` (3) | **нет совсем** | нет |
| `/o-proekte`, `/contact` | generic «Жемчужина Вятки» (не отличается от других страниц) | нет |
| `/posts`, `/search` | есть | нет |

То есть «часть страниц без title» — это не несколько лендингов, а целые разделы
(афиша, услуги, витрина) вместе с их карточками: **28 документов + 3 списка**.

## Почему

Две независимые причины, и обе не про контент:

1. **У маршрутов не было метаданных-экспорта вообще** — ни `metadata`, ни
   `generateMetadata` в `page.tsx`. Страницы рендерились, ссылки в сайтмапе
   были, а `<title>` не отдавался никем.
2. **`generateMeta` не имел фолбэка.** При пустом `meta.title` (а у `o-proekte`,
   `contact` он пуст) подставлялось имя сайта — то есть заголовок был, но
   одинаковый на всех таких страницах. `description` пробрасывался как есть:
   `doc?.meta?.description` без альтернативы, поэтому пусто у всех, кто не
   заполнил SEO-поле руками.

## Что сделали (PR #327, в проде после деплоя)

- `web/src/utilities/generateMeta.ts`: вход стал структурным `MetaDoc`
  (`title`/`slug`/`summary`/`meta`) — одна функция на `pages`, `posts`,
  `events`, `services`, `products`. Заголовок: `meta.title` → `title`
  документа (суффикс сайта один раз). Описание: `meta.description` →
  `summary` документа → описание сайта вместе с заголовком страницы.
- **Второй заход в тот же день:** у VK-импорта `title` — целая строка поста, и
  первый вариант отдал `<title>` длиной **192 знака** (в выдаче всё равно
  обрезается, но выглядит как авария). Добавили мягкое усечение по границе
  слова — **только для `doc.title`**, `meta.title` из админки не трогаем:
  там текст задан руками, обрезать его значит спорить с автором.
- `events`/`services`/`shop`: `metadata` у списков, `generateMetadata` у карточек.
- `/posts` (и пагинация) и `/search`: добавлен `description`.
- **Данные в БД не правились.** Это отдельно важно: описания выводятся из уже
  существующих полей, значит по versioned-докам не понадобился ни сырой SQL
  (он бы не дошёл до плагина поиска и был бы затёрт следующей публикацией), ни
  разовый Local API-прогон на проде.

Пункт 3 (регион «Малмыж») и пункт 4 (Яндекс Бизнес) остаются у вас/владельца —
со стороны сайта там делать нечего.
