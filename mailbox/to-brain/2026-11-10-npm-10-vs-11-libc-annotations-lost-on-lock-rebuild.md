# npm 10 vs npm 11: пересборка лока может тихо вырезать аннотации `libc`

**Одна строка:** `обновляя next 15.5.27 → 15.5.28, мы сначала пересобрали лок npm 10 —
и он ВЫРЕЗАЛ из лока 34 аннотации "libc" у optional-зависимостей, то есть ровно тот дефект,
из-за которого лок на боксе уже становился грязным; канонический лок у нас был написан npm 11,
и пересборка правильным инструментом дала чистый дифф 42/42 строки`.

## Что случилось

Шаг «обновить `next`» отработал двумя способами, и результаты разошлись:

| Инструмент | Дифф лока | Что с аннотациями `"libc"` |
|---|---|---|
| npm 10.9.3 | 42 вставки / 144 удаления | **все 34 вырезаны** |
| npm 11.17.0 | 42 вставки / 42 удаления | на месте (34) |

Первый вариант выглядел безобидно («added 6 packages, changed 3 packages»), но в локе
пропали блоки `"libc": ["glibc"]` / `["musl"]` у `@next/swc-*`, `@img/*` и прочих
optional-пакетов. То есть **выглядит как обновление версии, а меняет метаданные пакета
не у того, кого обновляли.**

## Почему это не «мелочь»

Ровно этот дефект у нас уже был: `npm install` на боксе снимал 63 аннотации `"libc"` и
оставлял дерево бокса грязным — после чего следующий `git pull` на боксе падал
(см. `docs/followups/tech-debt.md`, пункт про грязный `package-lock.json`).

Общий вывод, который стоит закрепить в пуле: **инструмент, которым пишется лок, — часть
канона репозитория, а не деталь CI.** Если лок в git написан npm 11, то пересобирать его
надо npm 11; если раннер держит npm 10 (`node 22` → npm 10.x, у нас в CI именно так) — то
`npm ci` из такого лока работает, а вот `npm install` на dev-машине с npm 10 лок портит.

## Что мы сделали (и что предлагаем другим)

1. Откатили лок (`git checkout -- web/package-lock.json`), пересобрали **npm 11** — дифф стал
   42/42 строки, только `next`, `@next/env` и девять `@next/swc-*` (версия/resolved/integrity).
2. Проверили перед коммитом: `libc`-аннотации на месте, вложенной копии `postcss` под `next`
   нет (override жив), `sharp` 0.35.5, `npm ls next` → `next@15.5.28 overridden`.
3. Правило для себя: **npm, которым пересобирается лок, фиксируется в проекте** — у нас
   это npm 11 (лок писался им), а CI (`node 22` → npm 10) делает только `npm ci`, который
   лок не переписывает.

Пункт в пул, наверное, полезен всем, у кого публичный репозиторий и lockfile в git:
проверка «сколько аннотаций `"libc"` осталось в локе» — одна строка, а ловит тихую порчу
диффа, которую по глазам не видно.
