# Два пункта из пятёрки — закрыты

## G194 (греп overrideAccess + поля-привилегии) — класс отсутствует

Проверено по всем 16 роутам с `overrideAccess: true` (`web/src/app/api/**`, `web/src/server/**`):

- Ни одного спреда клиентского тела в `data` (`...body` / `data: body` — 0 совпадений):
  все записи передают **явные литералы, выбранные сервером** (напр. чат: `isModerated: false`
  захардкожен, UGC-модерация: `status:'hidden'` ставит хук жалоб).
- Поля-привилегии UGC (`status`, `hiddenReason`, счётчики) закрыты field-access
  (`adminOrEditorField` на create/update) — публичный REST-путь (`create: anyone`)
  их задать не может; сервер меняет их осознанно через overrideAccess.
- `bookings` идёт даже с `overrideAccess: false` (валидация полным стеком).
- `user` в local API не прокидываем, но и не полагаемся на `req.user` в хуках этих коллекций —
  второй половины симптома G194 (гейт ловит собственный сервер) нет.

## Веб-аналитика — код на проде (PR #166, 2026-07-29)

Метрика + LiveInternet, consent-first (152-ФЗ), отложенная загрузка. Отличие от рецепта #051:
**не** `NEXT_PUBLIC_*` — с переездом сборки в CI (наш 2026-06-11) NEXT_PUBLIC запекается в
бандл из GH-secret, «выключаемо без деплоя» не выполняется. Вместо этого крошечный
force-dynamic `/api/analytics-config`, читающий runtime-env бокса → toggle = правка
`/etc/gonba/gonba.env` + restart, без пересборки. Возможно, пригодится другим проектам
с CI-standalone сборкой (кандидат в поправку #051).

G80 учтён: LI-URL собран вендорным конструктором с `escape()` один в один.

**Осталось от владельца:** завести счётчик Метрики + регистрация LI по домену →
`YM_COUNTER_ID` / `LI_ENABLED=1` в env. До этого счётчики выключены (ни баннера, ни JS).
Финальный ack «поехало на проде» пришлю, когда владелец даст номера.
